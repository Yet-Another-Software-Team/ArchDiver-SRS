\section{User Stories and Use Cases}
\label{section:user-stories-use-cases}
<TIP: For each stakeholder, write user stories that capture what
they need from the system: "As a [stakeholder], I want to [action] so that [benefit]."
For your most important user stories, expand them into use cases.
A use case is a detailed description of how a system
interacts with an external entity (such as a user or another system) to
accomplish a specific goal. Use cases provide a high-level view of the
functionality of a system and help in capturing and documenting its
requirements from the perspective of end users.

Make sure to use the
appropriate type of use case for each scenario (brief, casual, and fully-dressed
use case). />
\subsection{User Stories}
\label{subsection:user-stories}

\begin{description}[style=multiline, leftmargin=2cm, font=\normalfont]
    \item[\textbf{US-01:}] As a \textbf{Software Architect}, I want to visualize the software architecture in a graph format so that I can identify systemic dependencies and potential structural issues at a glance.

    \item[\textbf{US-02:}] As a \textbf{Software Architect}, I want to receive natural language explanations for flagged architectural smells so that I can understand the impact of a structural flaw without manually calculating complex metrics.

    \item[\textbf{US-03:}] As a \textbf{Lead Developer}, I want to parse code written in different languages into a unified representation so that I can maintain consistent architectural standards across a multi-language codebase.

    \item[\textbf{US-04:}] As a \textbf{DevOps Engineer}, I want to execute architectural analysis via a command-line interface so that I can automate structural integrity checks within our Continuous Integration (CI) pipeline.

    \item[\textbf{US-05:}] As a \textbf{Researcher}, I want to export architectural metrics into a standardized format so that I can use the raw data for further quantitative analysis or custom reporting.

    \item[\textbf{US-06:}] As a \textbf{Lead Developer}, I want to interact with the architectural graph (zooming/filtering) so that I can isolate specific components or clusters that are exhibiting highly coupled behaviors.
\end{description}
