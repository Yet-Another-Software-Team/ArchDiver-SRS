\section{User Stories and Use Cases}
\label{section:user-stories-use-cases}

This section lists the primary user stories followed by compact, run-in formatted use cases. Use cases present metadata in a single-line-per-field style to reduce large vertical gaps and improve scanability.

\subsection{User Stories}
\label{subsection:user-stories}

\begin{description}
    \item[US-01: Visualize Architecture:] As a \textbf{Software Architect}, I want to visualize the software architecture as an interactive graph so I can identify dependencies and structural issues quickly.
    \item[US-02: Explain Smells:] As a \textbf{Software Architect}, I want natural language explanations for flagged architectural smells so I can understand their impact without manual metric computation.
    \item[US-03: Multi-language Parsing:] As a \textbf{Lead Developer}, I want the system to parse code written in multiple languages into a unified intermediate representation so consistent architectural checks apply across the codebase.
    \item[US-04: CLI Integration:] As a \textbf{DevOps Engineer}, I want to run architectural analysis via a CLI so I can integrate checks into CI pipelines.
    \item[US-05: Exportable Metrics:] As a \textbf{Researcher}, I want to export architectural metrics in standard formats so I can perform further quantitative analysis.
    \item[US-06: Interactive Graph Controls:] As a \textbf{Lead Developer}, I want to zoom, filter, and focus the architectural graph so I can isolate high-risk components or clusters.
\end{description}

\subsection{Use Cases}
\label{subsection:use-cases}

The use cases below are presented with compact metadata rows (Primary Actor, Goal, Precondition) followed by a concise main success scenario and extensions.

\subsubsection{UC-1: Initialize Project Analysis}
\label{subsubsection:uc-1}
\begin{tabularx}{\textwidth}{@{}p{3.2cm}X@{}}
Primary Actor: & User (Architect, Developer, Researcher) \\
Goal: & Parse a target codebase and produce an initial analysis dashboard. \\
Precondition: & None. \\
\end{tabularx}

Main success scenario:
\begin{enumerate}
    \item The user selects a project directory.
    \item The system parses source files and extracts components and relationships into the TOML intermediate representation (IR).
    \item Static metrics are computed, and the dependency graph is constructed.
    \item The GraphSAGE model evaluates nodes for likely architectural smells.
    \item The dashboard and graph canvas are populated with parsed modules, computed metrics and visual indicators of detected smells.
\end{enumerate}

\subsubsection{UC-2: Visualize Architectural Dependencies}
\label{subsubsection:uc-2}
\begin{tabularx}{\textwidth}{@{}p{3.2cm}X@{}}
Primary Actor: & User \\
Goal: & Explore system structure to identify problematic components and dependency patterns. \\
Precondition: & A parsed project with computed metrics and a dependency graph is available. \\
\end{tabularx}

Main success scenario:
\begin{enumerate}
    \item The user opens the Graph Visualization canvas.
    \item The system renders a node-link diagram representing components and directed dependencies.
    \item The user interacts (pan/zoom) and clicks a node to view detailed metrics in a sidebar (e.g., complexity, fan-out, fan-in).
    \item The user applies filters (severity, language, package) and chooses layout options (force-directed, hierarchical).
    \item The user identifies hotspots (e.g., high coupling or cyclic dependencies) and drills down using graph controls or clustering controls.
\end{enumerate}

Extensions:
\begin{itemize}
    \item For very large graphs, the system uses clustering or progressive rendering; clusters can be expanded on demand for detail.
\end{itemize}

\subsubsection{UC-3: Triage Smell with XAI Justification}
\label{subsubsection:uc-3}
\begin{tabularx}{\textwidth}{@{}p{3.2cm}X@{}}
Primary Actor: & User \\
Goal: & Inspect an identified smell, obtain a human-readable justification (XAI), and navigate to the related graph location. \\
Precondition: & The project has been analyzed and smells were detected. \\
\end{tabularx}

Main success scenario:
\begin{enumerate}
    \item The user opens the \textit{Detected Smells} view.
    \item The system lists smells with severity, affected component and supporting metrics.
    \item The user expands a smell card to see important metrics and an XAI-produced explanation including confidence indicators where available.
    \item The user requests additional context (e.g., historical metrics or code excerpts) if provided by the system.
    \item The user clicks a \textit{Related Component} link to focus the graph canvas on the implicated node and inspects its neighborhood.
\end{enumerate}

Extensions:
\begin{itemize}
    \item XAI/LLM fails or times out: display raw metrics with a standard, non-AI definition of the smell and a \textit{Retry Explanation} action.
    \item Missing metrics (parser limitations): mark unavailable metrics and provide a best-effort explanation or suggestion to enable additional parsers.
\end{itemize}

\subsubsection{UC-4: Analyze Project with CLI}
\label{subsubsection:uc-4}
\begin{tabularx}{\textwidth}{@{}p{3.2cm}X@{}}
Primary Actor: & User \\
Goal: & Execute the architectural analysis via command-line interface for automation or headless environments. \\
Precondition: & Source code is available locally and the CLI tool is installed. \\
\end{tabularx}

Main success scenario:
\begin{enumerate}
    \item The user executes the analysis command in the terminal, specifying the target project directory and optional configuration flags.
    \item The system parses the codebase, computes metrics, and runs the GraphSAGE model without launching the graphical interface.
    \item The system generates a summary report of detected architectural smells in the terminal standard output.
    \item The system optionally exports the detailed analysis results to a specified structured file format (e.g., JSON, CSV).
\end{enumerate}

Extensions:
\begin{itemize}
    \item Invalid directory or missing permissions: The system outputs a standard error message and terminates with a non-zero exit code.
\end{itemize}

\subsubsection{UC-5: Configure Analysis Settings}
\label{subsubsection:uc-5}
\begin{tabularx}{\textwidth}{@{}p{3.2cm}X@{}}
Primary Actor: & User \\
Goal: & Adjust project-specific parameters, such as metric thresholds and XAI preferences, to tailor the analysis. \\
Precondition: & None. \\
\end{tabularx}

Main success scenario:
\begin{enumerate}
    \item The user navigates to the Analysis Settings interface.
    \item The user modifies structural thresholds (e.g., defining the maximum acceptable Cyclomatic Complexity or Fan-Out values).
    \item The user toggles specific processing features, such as disabling LLM-based XAI generation to prioritize faster analysis times.
    \item The user saves the configuration.
    \item The system applies the updated parameters to subsequent parsing and smell detection operations.
\end{enumerate}

Extensions:
\begin{itemize}
    \item Invalid threshold inputs (e.g., negative complexity values): The system highlights the invalid field, prevents saving, and prompts the user for a valid input.
\end{itemize}

\section{User Interface Design}
\label{section:user-interface-design}

Primary screens (brief):
\begin{itemize}
    \item \textbf{Workspace Home:} Summary metrics (modules, smells by severity), and start new analysis workflow.
    \item \textbf{Graph Visualization:} Interactive node-link canvas with sidebar for details, filters, clustering, and layout controls.
    \item \textbf{Detected Smells:} Card or list view with severity, supporting metrics and expandable XAI explanation panel.
    \item \textbf{Analysis Settings:} Configure project-specific thresholds, and triage criteria to tailor the analysis.
